# Публикация «Квестограда» в Netlify

Нужен Node.js 24 и аккаунт Netlify с правом создавать или публиковать сайты. Конфигурация сборки и функций находится в `netlify.toml`.

## Доступ

Добавьте `NETLIFY_AUTH_TOKEN` в защищённые переменные среды. В облачной среде токен должен передаваться через поддерживаемую привязку секрета к HTTPS-домену `api.netlify.com`. Не отправляйте значение в чат, не записывайте в Git или команды shell. При работе через Netlify UI авторизация выполняется самим Netlify.

Необязательная переменная `NETLIFY_SITE_ID` выбирает существующий сайт. Если её нет, скрипт использует `siteId` из игнорируемого файла `.netlify/state.json`. Если сайт ещё не выбран, скрипт создаст `kvestograd-<случайный суффикс>` в вашем аккаунте и сохранит ID **до** запуска публикации. Повтор после неудачной сборки использует тот же сайт.

```sh
npm ci
node scripts/deploy.mjs --check
node scripts/deploy.mjs
```

`--check` проверяет только авторизацию. Основная команда проверяет выбранный сайт через API и получает его актуальное имя, затем выполняет два шага:

```sh
netlify build --offline
netlify deploy --prod --no-build --site <проверенное-имя> --dir dist --functions netlify/functions --json
```

Первый шаг собирает клиент и серверные функции по `netlify.toml` без сетевого поиска необязательных расширений. При ошибке сборки публикация не запускается. Второй шаг публикует готовый клиент и серверные функции; адрес сайта вернёт CLI. В `--site` передаётся имя из ответа API: это также работает при переходе CLI к offline-конфигурации из-за недоступного сервиса расширений. Привязка для повторных запусков по-прежнему сохраняет ID сайта.

Токен передаётся через окружение, а не аргументы процесса. Скрипт использует настроенный HTTPS-прокси и сохраняет проверку TLS. Сайт не создаётся повторно после неудачной сборки или публикации.

Проверка сборки без публикации:

```sh
npm run build
npx netlify build --offline
```

`npm run preview` проверяет клиент и локальные API, но не подтверждает работу Netlify Blobs в production. При первом реальном обращении к `/.netlify/functions/quest` или создании дуэли нужно отдельно убедиться, что сайт отвечает успешно.

## Хранилище заданий и сетевых комнат

Production использует Netlify Blobs в том же сайте. Дополнительный SQL-сервер или отдельный пароль БД не нужен: доступ функциям предоставляет Netlify.

При первом запросе автоматически создаётся документ `questions-v1` в хранилище `questograd-content`. Он содержит `{ version: 'v1', updatedAt, questions }`. Начальный проверенный банк берётся из `src/data/questions.ts`; новые варианты формируются генератором `src/data/generator.ts`. Документ с уже существующими заданиями не перезаписывается; неверный формат возвращает ошибку вместо потери данных. Для обновления банка используйте инструменты Netlify Blobs, сохраняя его версию и схему. Процесс функции кэширует проверенный банк до 60 секунд.

Сетевые комнаты хранятся отдельно в `kvestograd-duels`, доступны по коду и токену игрока и действуют 2 часа. Согласованные атомарные обновления предотвращают потерю очков при одновременных ответах. После срока комнаты данные могут сохраняться в хранилище, но API больше не допускает игру в ней.

Локальный `npm run dev` использует те же API и проверку схемы, но хранит банк и комнаты в памяти. Перезапуск локального сервера очищает их.

Для отдельной проверки настоящих Netlify Functions и локального Blobs без публикации:

```sh
npx netlify functions:serve --offline --port 8888
```

Эта команда обслуживает `/.netlify/functions/quest` и `/.netlify/functions/duel` на выбранном локальном порту. В облачной рабочей среде при недоступном домашнем каталоге задайте `XDG_CONFIG_HOME=/workspace/.cache/netlify-config`. Файлы эмулятора остаются в игнорируемом `.netlify/`. Полный `netlify dev` также пытается подготовить Deno для Edge Functions, даже если проект их не использует; в среде с ограниченной сетью это может завершиться ошибкой. Отдельный `functions:serve` не требует Edge runtime.

У локального эмулятора `@netlify/blobs` 11.1.5 есть ограничения: GET не возвращает ETag, а проверка условной записи не атомарна при одновременных запросах. Адаптер обходит отсутствие ETag только в локальном режиме через стабильную пару LIST/GET/LIST, сохраняя условные записи. Настоящие функции и полный раунд из восьми вопросов проверены с последовательными ответами; этот эмулятор не подтверждает устойчивость к одновременным записям. Для обычной локальной игры рекомендуется Vite с атомарным адаптером в памяти. Production использует документированный атомарный API Netlify Blobs и требует проверки на опубликованном сайте; отсутствие production ETag возвращает ошибку, а не разрешает небезопасную запись.

## Прогресс игроков

Без подключения к семье два профиля сохраняются в браузере. После подключения через одноразовый код из `/parent` профиль, XP и годовой маршрут сохраняются в приватном `kvestograd-family` и восстанавливаются на подключённых устройствах. Очистка браузера удаляет локальную очередь и ключ устройства; для облачного восстановления нужен новый код родителя. Очки сетевой дуэли относятся к комнате; её итог доступен родителю и не заменяет одиночный XP.

Первичная настройка владельцем сайта:

```sh
node scripts/prepare-parent.mjs
npm run deploy
```

Скрипт получает существующий сайт, генерирует случайный токен 256 бит, сохраняет его только в игнорируемом `.netlify/parent-activation.json` и приватном `/workspace/parent-access.html` с правами 0600. В серверную переменную Netlify `PARENT_BOOTSTRAP` записываются **только SHA-256 проверка и срок 7 дней**. На бесплатном тарифе используются все области переменной, как в Netlify CLI (`post_processing` с подчёркиванием); имени `VITE_` у неё нет, поэтому клиент её не получает. Значения и ссылки не выводятся в логи. После deploy передайте приватный HTML-файл владельцу: в нём кнопка для одноразового создания пароля. После активации повторная ссылка не создаёт и не сбрасывает аккаунт.

Если родитель потеряет пароль, публичного сброса нет. Требуется отдельное авторизованное восстановление владельцем Netlify; не удаляйте аккаунт или детские документы автоматически. Уже существующие семейные данные и аккаунты при деплое сохраняются.

Кабинет защищает серверная роль, cookie на 8 часов, scrypt с солью, ограничение попыток входа и проверка Origin. Детские токены сохраняются только на доверенных устройствах и позволяют синхронизировать оба игровых профиля; родитель может их отозвать. Не сохраняйте родительский пароль или cookie в localStorage. Подробная история разбита по дням; атомарные условные записи не допускают потери ответов при одновременной игре.

Production-проверка `status` должна возвращать HTTP 200 и `activationAvailable: true` до первого входа; без cookie `dashboard`/`history` возвращают 401. Не расходуйте персональный токен владельца для smoke-теста. Полный вход, миграция, офлайн-синхронизация, CSV и отзыв доступа проверяются `e2e/parent.spec.ts` с автоматически сгенерированным локальным bootstrap на свежем сервере.
За первый верный ответ на конкретный вариант начисляется 8, 12 или 16 XP. Повтор ранее решённого задания не даёт опыта. Для ограничения размера браузерного хранилища запоминаются последние 10 000 решённых вариантов; очень старый вариант после вытеснения может снова дать опыт. Задания не содержат рекламы; для игры не требуются фамилия, электронная почта, камера или микрофон.

## Проверка опубликованного годового маршрута

Текущий сайт: https://kvestograd.netlify.app. Переименование проекта в Netlify сохраняет его ID; скрипт каждый раз получает актуальное имя через API. В облачной среде разрешённый домен должен соответствовать текущему адресу сайта.

```sh
npm run test:production -- https://kvestograd.netlify.app
```

Проверка делает реальные запросы к опубликованным функциям: задания всех предметов, годовые квесты, чтение и полную дуэль двух игроков с одновременными ответами, повторной отправкой и проверкой победителя. Она создаёт одну тестовую комнату и не выводит токены игроков.

Материал чтения автоматически записывается отдельным документом `questograd-content/reading-v1` (26 текстов, 208 вопросов), сохраняя прежний банк `questions-v1`. Существующие документы не перезаписываются, неверный формат вызывает ошибку. Тексты передаются в поле `passage` отдельно от вопроса и проверяются перед использованием.

Для `@netlify/blobs` 11.1.5 дополнительно проверяется протокол условной записи: HTTP 409 обрабатывается как конфликт и повторяется, прочие ошибки записи не выдаются за успешное сохранение. Это предотвращает подтверждение потерянных ответов при гонке обновлений.
